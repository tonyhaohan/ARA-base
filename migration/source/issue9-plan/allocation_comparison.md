# 1MiB QP 分配策略对照

每个有向 GPU pair 发送 1MiB，即 `1,048,576B` 或 256 个4KB小包。实验覆盖四个代表性 `(N,M,Q)` 拓扑和每条物理路径 `R=1,2,4` 个 QP，共 12 组配对 case。hash 与 round-robin 使用相同 ASTRA/ns-3 二进制、物理路径、QP 定义和 native trace 校准结果。

## 结论

round-robin 的 12 个 case 全部成功，PFC event 为 0，总字节与 FCT 行数守恒。因为 256 能被本次所有 QP group size 整除，round-robin 在每个逻辑流内的 QP小包数最大差值均为 0；hash 的最大差值为 32。在 `(4,2,2,R=4)` 中，hash 的 384 个配置 QP 只有 382 个实际获得小包，round-robin 使用全部 384 个。

round-robin 相对 hash 的完成时间平均降低 5.02%，范围为 0.00% 到 8.90%。多物理路径 case 均有 4.82% 到 8.90% 的改善；`N=2,M=1,Q=1` 只有一条物理路径，因此即使多个 QP 的小包数更均匀，完成时间也不变。平均理论差距从 hash 的 22.77% 降至 round-robin 的 16.35%，最大理论差距从 35.43% 降至 23.38%。

结果支持把 round-robin 设为默认 QP选择策略，并保留显式 hash 作为近似均匀的对照选项。该变更只发生在 bridge 的4KB小包分配和基准入口，不修改 ASTRA适配层或 ns-3 网络层。

原始运行产物位于忽略目录 `runs/issue9_1mib_allocation_compare/`，包含 24 个 case 的 `summary.json`、`summary.csv`、QP plan、FCT 和运行日志。
