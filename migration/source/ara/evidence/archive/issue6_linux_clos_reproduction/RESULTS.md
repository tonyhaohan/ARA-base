# 单层 Clos：Linux 服务器复现结果

日期：2026-09-15。结论：四个代表拓扑的 R=1 切片已在租用的 Linux 服务器运行并验收。最小案例与历史表一致，其他旧 hash 对照相差不超过 0.1843%；当前均匀分配的理论差距均低于 8%。这不是全网格、全部 R 或 MCNF Allreduce 的完成声明。

## 固定实验设置

每张卡向其他每张卡各发送 8,000,000 字节，十进制 8 MB，不是 8 MiB。每条物理链路为 400 Gbps、传播延迟 500 ns，4KB小包为 4096 字节；所有配置每条完整物理路径放一个 QP，即 R=1。QP 是固定到物理路径的发送通道。仅对比小包如何选择 QP：hash 近似均分与 round_robin 依序均分。

理论时间按纯数据量与端口带宽计算：`T = 160*(N-1)/(M*Q)` 微秒。N 是卡数，M 是并行交换机数，Q 是每对卡—交换机的平行链路数。理论差距为 `(仿真时间/理论时间-1)*100%`，始终不把带协议开销的另一参考值替换为分母。

未修改带宽、传播时延、包大小、ACK、拥塞控制或任何仿真器/求解器源码。桥接代码为 `1d4f816a542f46ff0d1c99af6ce2d8b097822303`，ASTRA 为 `181c7856ed77bac3be68495e2400752488df5e5a`。服务器 Ubuntu 22.04.5、x86_64、Python 3.10.12，复用本次首次部署时编译的 ASTRA/ns-3 二进制。

所有时间单位均为微秒；每行对应一整个 All-to-all 通信任务，而非某条流的平均值。历史列来自 `docs/plans/issue6_qp_config_groups/qp_per_path_coarse_results.md` 的 R=1/hash 记录。

四个均匀分配案例理论差距范围为 3.88%～6.39875%，算术平均为 5.20708%。这四个案例已低于师兄提出的 8% 上限方向；低于 5% 的两个案例更接近纯带宽理论值，不需要人为调高到 5%。不能声称完整单层 Clos 网格均已达到该目标。

## 复现程度及限制

最小案例 166.208 微秒与历史表相同。其他三个 hash 案例相对历史分别变化 -0.09550%、-0.18428%、-0.16686%；因此是近似复现，不是四个案例全部逐纳秒复现。历史表只保留三位微秒精度。

已核对主要配置、显式 hash 算法和 QP 构造逻辑保持一致。旧结果来自 macOS 的此前构建，本次为 Ubuntu/GCC；旧批次的完整二进制、配置与 FCT 不在当前本地副本，跨构建细微差异的具体原因仍未定位，不能直接归因于浮点、ACK 或校准的 R。校准最大 R 不决定正式案例的 R，不能未经验证拿它解释差异。

## 验收证据

正式批次是 4 拓扑 × 2 分配策略 × 2 遍，共 16 次性能运行。每种配置两遍的完成时间逐纳秒一致；16 行均成功，FCT 条数、原始传输字节和每张卡完成记录一致。2 卡任务总传输 16,000,000 字节，4 卡任务总传输 96,000,000 字节。16 次共核对 520 条 QP 完成记录。均匀分配每逻辑流的小包数差不超过 1；8 MB 不是 4096 的整数倍，尾部仅512字节，因此均匀的小包数不意味着所有 QP 字节数完全相等。

重新读取了全部 16 份独立校准原始 trace，核对 520 次 QP 逐跳路径，并对 8 组策略配对逐字节核对物理拓扑、网络配置、系统配置，逐项核对 QP、路径、分组、逻辑流和 hashSeed。正式性能案例没有开启逐包 trace；路径证据来自参数一致的独立校准。

验收工具输出 `PASS; 0 errors`，路径复核输出 `NATIVE_PATH_AUDIT_OK: 16 calibrations; 520 QP paths; 8 paired input checks`。工具另报8条提示：不同运行的校准原始文件哈希不同；每份文件与其自身引用均匹配，重新解析的路径均通过。不能把这种跨运行原始文件差异与同目录覆盖造成的错误混为一谈。所有正式案例的 PFC 原始事件数为0，未发现运行 stderr/错误日志异常；校准轨迹未检测到 UDP 数据丢包，但这不等于已逐包证明正式案例完全无重传。

所有运行记录的二进制 SHA256 相同，且已在服务器对实际 ELF 文件独立运行 sha256sum 核对：`7f9db19d50dafbe8d371c9f64cbef8b9e7b27cb7794fb1c62e6be8956ade67f4`。主分析工具自身只核对指纹元数据；本段二进制检查和独立路径复核是额外证据。

包含新增研究记录的Linux隔离快照，70项自动测试全部通过（1.81秒）；ARA结构为36节点、54边、33条证据、12条claim、5个session并校验通过。只把记录测试中固定的32节点/4session同步到新增后的36/5，不改仿真行为。Windows本地另有既有的macOS路径模拟测试受盘符冒号影响失败，本轮未修复；上述通过结果来自实际运行仿真的Linux平台。

## 保留的失败尝试

第一批 `clos_reproduction_20260915_dXbRHT` 把两策略放在同一 run-root，并分别使用 --force，导致后一次校准覆盖前一次 trace，旧 summary 仍引用旧哈希。虽然数值稳定，但独立验收准确报告8处 trace 引用不匹配。该批完整保留，标为证据归档失败，不当作正式验收依据。

只修改外层包装脚本，把路径改为 first/hash、first/round_robin、repeat/hash、repeat/round_robin，重新运行得到了本报告正式批次。没有改核心 runner、输入参数、旧 summary 或校验规则。本轮还没有修复核心 runner 在共享目录 force 重跑时的证据保留行为；后续复用时应遵守策略隔离。
