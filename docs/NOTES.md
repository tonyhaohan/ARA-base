# Issue 研究纪要与按需读取规范

本规范适用于当前仓库的研究纪要。文件布局和结构化字段以 PROTOCOL.md 为准。

## 职责

每个研究 Issue 对应一个研究分支、一个 ExecPlan 和一份研究纪要。

- ExecPlan 保存完整用户原话和追加式执行历史，遵循 MCNF_tree 当前约定。
- 研究纪要保存实验条件、各 idea 的研究过程、结果、解释和证据入口。
- idea DAG 保存 `id`、`depends_on`、`primary_dependency` 及纪要文件定位；不手写后继。
- Issue 索引在收尾时由 agent 单独归纳；不强制与 idea 依赖逐边一致。
- claim、observation、转换与修订事件仍有稳定 ID 和结构化关系，纪要引用它们，不把这些关系只埋进段落。

建议纪要位置为 `ara/issues/issue123.md`。DAG 定位可采用 `record: ara/issues/issue123.md#I123-N01`，这里的片段是提取器使用的逻辑 ID，不依赖不同 Markdown 渲染器生成的网页锚点。把 ID 和文件路径交给提取器即可。

## 虚拟根

保留 `I000-N00` 作为全局虚拟根，仅表示研究起点。

- 根节点的 `depends_on` 为空，没有主要依赖。
- 没有实际前置 idea 的研究起点依赖根，主要依赖也为根。
- 有实际前置 idea 时只引用实际节点，不再附加根。
- 主要依赖必须包含在依赖列表中；全部后继由解析器反向生成。
- 根不对应真实 Issue #0、分支、实验、证据或纪要章节，也不计入真实研究节点数量。
- 根的连接不表示科学证据；可视化应标记为“研究起点”。

## Markdown 章节规则

固定使用以下层级：

1. `# Issue #123 — 研究主题`：文档唯一 Issue 标题。
2. `## 统一信息`：必须先出现，正文非空。
3. `## I123-N01 idea 标题`：每个 idea 一个二级章节，ID 唯一，正文非空。
4. 章节内部只使用 `###` 及更深标题；不再使用其他二级标题。

提取范围为“文件开头至第一个 idea 之前”加“指定 idea 标题至下一 idea 标题之前”。空行和内容原样保留；不会读取或展开前置 idea 的正文。

二级标题必须从行首开始，以 `## ` 开头。不使用 Setext 标题、引用块、HTML 注释或列表来隐藏这些章节标题。代码块使用成对的反引号或波浪线围栏；围栏中的标题只是代码内容。

前置说明及脚注、引用式链接定义应放在公共部分或使用它的 idea 章节内，不要把全篇共用定义放在最后一个 idea 末尾。跨 idea 引用只写稳定 ID；需要其内容时再次按需提取。

ID 数字位数不限。建议 Issue 至少三位、节点至少两位，如 `I123-N01`；`I123-N01` 与 `I0123-N001` 不允许被当成两个不同节点。根只存在于图中，不能成为纪要章节。

## 统一信息与差异覆盖

公共部分保存短的共享说明和一个 YAML 条件块；字段只在有关时填写，不用空表格凑齐。

- 研究范围、指标定义和单位；它们决定各结果能否比较。
- 代码仓库、确切版本；有未提交改动时记录可取得的源码快照或补丁及校验值。
- 环境、硬件、软件版本、数据版本和公共配置。
- 执行入口、配置文件、数据及证据的路径基准。

各 idea 只记录条件差异。`overrides` 使用从公共条件根开始的点分键，例如 `config.batch_size: 64`、`environment.host: worker-b`；相同键以当前 idea 为准。配置键本身不包含点。无差异写 `overrides: {}`。这里是撰写契约，当前脚本只提取原文，不解析 YAML 或合并配置。

**公共条件在首次实验后冻结。** 后续变化写在相关 idea 的差异中，不能通过改写文件顶部让历史实验看起来使用了新条件。重要纠错追加说明其依据和受影响的 idea；完整变更经过保留在追加式 session/ExecPlan 中。

公共部分保持短小，长的环境清单、锁文件和完整配置通过有版本或校验值的路径引用。路径统一相对于记录的项目根或稳定归档根；提取脚本不解析、改写或获取它们。

## idea 章节最少保存什么

使用短 YAML 元数据块保存来源、时间、条件差异及 observation/claim/evidence 引用。正文使用 PROTOCOL.md 规定的英文三级字段标题（如 `### hypothesis`、`### method`、`### result`），以便按类型校验；字段内保留自然语言。内容覆盖：

- **问题与假设**：试图回答什么，什么结果会推翻判断。
- **方法与复现**：做了什么；完整可运行命令或确切运行清单入口。
- **结果与证据**：关键原始指标和单位；失败、超时等结果同样保存。
- **解释与边界**：结果支持什么，尚不能说明什么，失败学到了什么。
- **结论形成或修订**：引用 session 中的转换事件 ID，不重复维护事件历史。

每份关键证据都应能定位、核对身份、找到复现入口，并直接检查小结果。公共条件中已经给出的信息由章节继承；每次运行特有的产物路径和校验值放在章节证据里。未知值写“待取得”或 `null` 并解释，不能编造。

理论推导、问题、决定和转向也可以是 idea；按其实际内容记录，不强造实验、运行命令或数值。后续复跑在同一 idea 内追加三级或四级小节，并标明本次差异，原结果不覆盖。

Markdown 是详细记录的载体，不等于放弃结构化。依赖、来源、证据绑定、主张状态、观察去向及修订关系继续用固定字段或 ID 表达；方法、解释和适用边界可以用自然语言。

## 使用

在项目根运行：

```sh
python scripts/ara.py issues
python scripts/ara.py ideas --issue 3
python scripts/ara.py read I003-N01
python scripts/ara.py show I003-N01
```

`read` 返回公共部分和目标章节；`show` 返回结构化条目、自动反推的后继和相关事件。需要直接读取未接入索引的符合规范的纪要时，使用 `python scripts/notes.py FILE ID`。仅省略 ID 会列出章节标题。

脚本在本地读文件，但只把选中内容写到输出，不自动展开前置idea、外部配置或原始日志。Markdown章节解析检查代码围栏、ID和边界；结构化语义由主验证器检查。

历史迁移条件缺失与旧状态转换，按 PROTOCOL.md 的“历史迁移契约”处理，不把未知条件填成没有变化。
